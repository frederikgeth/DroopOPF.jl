# IEEE AVR qualification lane

These artifacts are generated by `examples/avr_ieee_qualification.jl`. Each
run first solves the untouched local PGLib IEEE case as bounded FreeQ, selects
one available terminal generator whose raw voltage is at least `1e-5` inside
its voltage bounds and has maximum normalized bidirectional Q headroom, then
replays the witness with one AVR assignment.

Files are deliberately separated by network and solver. A solver process that
does not produce an artifact is not a pass. This lane does not replace or
rescore the frozen synthetic-droop S1 matrices.

`summary_118_ccopt.json` records the bounded exact-solver process that exited
without a solver result; it is explicitly a non-pass, not missing evidence.

The `*_k3.json` files use the predeclared three-device set: highest normalized
bidirectional raw-Q headroom, at most one AVR per generator bus, and raw voltage
at least `1e-5` inside bounds. They are distinct from the earlier `k1` run.
`summary_300_madnlp_k3.json` is likewise an explicit non-pass: the bounded
three-device MadNLP process did not produce a solver result.

The load-stress artifacts retain the load factor for every cell. The direct
IEEE-118 three-device AVR-aware joint tap attempt produced no bounded artifact
and is retained as `summary_118_ipopt_k3_load1.0_joint.json`, a non-pass rather
than a feasibility conclusion. The staged continuation counterpart,
`summary_118_ipopt_k3_load1.0_joint_staged.json`, is valid: it activates the
same predeclared AVR set one device at a time, carrying the prior AC state and
tap start forward through k1, k2, and k3. Thus the direct non-pass is a
conditioning/initialization threshold, not a k3 joint-design infeasibility.
The same staged policy validates every k1, k2, and k3 stage at loads 1.00 and
1.01 on both IEEE-118 and IEEE-300 with both Ipopt and MadNLP. These eight
artifacts establish two independent smooth-solver joint-design envelopes.

The four `*_ccopt_*_joint_staged.json` artifacts are the bounded exact lane.
All four k3 AVR prerequisites are `LOCALLY_SOLVED` and valid. Eleven of twelve
joint stages are physically valid: both IEEE-118 cells pass all stages;
IEEE-300 nominal passes k1 and has valid `ALMOST_LOCALLY_SOLVED` k2/k3 stages;
IEEE-300 at load 1.01 has valid `ALMOST_LOCALLY_SOLVED` k1/k2 stages, followed
by an invalid `LOCALLY_INFEASIBLE` k3 stage. The exact lane is therefore 11/12
by independent physical validation and 7/12 under a strict `LOCALLY_SOLVED`
status gate.

`summary_300_ccopt_k3_load1.01_joint_cross_seed.json` diagnoses that sole
failure. An Ipopt k1 → k2 → k3 continuation supplies the complete k3 AC state
and tap to a fresh exact CCOpt solve. CCOpt then returns a physically valid
`ALMOST_LOCALLY_SOLVED` point with maximum complementarity residual
`2.484e-8`; its tap differs from the smooth seed by about `5.18e-9`. The
earlier `LOCALLY_INFEASIBLE` result is therefore basin-sensitive solver
behavior, not evidence that the exact stressed-k3 equations are infeasible.
