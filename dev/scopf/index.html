Security-constrained AC OPF (M2 and M9.1)

The SCOPF engine jointly optimizes one base dispatch and a declared set of line and generator outages. Droop settings remain fixed across scenarios. Each scenario has its own AC voltages, angles, active generation, and reactive generation. The joint formulation remains a small-network reference implementation. M10 also provides a separate conservative pre-solve filter for independent contingency assessment; it is not applied inside the joint SCOPF model.

M10 contingency catalog and baseline assessment

M10's core capability is network-size agnostic. Given any validated Case and fixed base ACState, evaluate_contingency_catalog evaluates every eligible entry independently and returns its solver result, independent report, and rank. contingency_screening_scores supplies deterministic within-device priority percentiles without classifying a low-scored outage as safe:

catalog = contingency_catalog(case)
assessments = evaluate_contingency_catalog(case, base_state;
    catalog, participation=participation)
scores = contingency_screening_scores(case, base_state; catalog)
decisions = filter_contingencies(case, base_state; catalog,
    loading_threshold=0.8, voltage_guard=0.02)
pipeline = assess_contingency_pipeline(case, base_state; catalog,
    audit_screened_ids=[:branch_11])
write_contingency_pipeline("pipeline.json", pipeline)

Use normal Julia compilation for performance runs. The supervisor no longer uses --compile=min, which slows numerical model construction. Power-balance expressions for the imported FreeQ baseline contain only nonzero admittance entries; this preserves the equations while avoiding dense derivative graphs. Declared reactive-control paths retain their existing expression ordering to preserve sensitive CCOpt warm-start trajectories. Each completed baseline writes timing.json separating construction (including first-call compilation) from optimization and extraction. Compare warm runs in the same Julia process when measuring sustained throughput; a fresh process pays compilation again.

contingency_catalog(case) deterministically enumerates every available line, transformer, and generator outage. Each candidate records its device ID and a structural disposition. Connected outages and generator outages are eligible; a line or transformer outage that islands the network is retained as excluded from the original single-component evaluator with reason islanding_unsupported. It can instead be passed to evaluate_islanding_contingency. That path retains the original-reference component unless another component has strictly more buses. If the larger component is selected, the bus of its available generator with greatest p_max becomes the reference (generator ID breaks ties). Only the retained component is balanced; discarded buses, load, and generation capacity are reported and are never classified as served or safe.

filter_contingencies is a conservative routing layer. Generator outages go to exact AC evaluation. Structurally islanding line and transformer outages go to the island-aware evaluator. Connected network outages use a DC LODF estimate and are screened only when predicted loading is below the declared threshold and the base voltage is outside the guard band. Singular or uncertain calculations, near-limit base voltages, and predicted thermal risk all fall back to exact AC evaluation. Screening is a workload decision, not an AC security certificate; thresholds require held-out reliability qualification before operational use.

assess_contingency_pipeline executes those routes and provides the integrated checks around them. It validates the base state, requires exactly one decision for every catalog entry, checks decision identity against the catalog, retains per-contingency evaluation errors, and independently validates every executed AC result. Generator outages always use exact fixed-base SCOPF assessment; islanding line/transformer outages use retained-component AC assessment; screened connected network outages remain explicitly screened_not_evaluated.

The optional audit_screened_ids list selects deterministic screened cases for an exact AC cross-check. An unresolved audited case becomes screening_audit_failure, moves to the top of the combined ranking, and makes the pipeline completeness check fail. screening_enabled=false converts every otherwise screened connected outage into an exact baseline run. The result reports routing_complete separately from full_ac_coverage and all_outcomes_accepted; therefore a successfully routed filtered run cannot be mistaken for complete AC security assessment. The result contains aggregate network, line, transformer, and generator rankings plus a combined operational ranking. The combined ordering uses explicit tiers—screening-audit failure, evaluation error, invalid result, island load loss, physical-only result, accepted exact result, then unaudited screened entry—before severity and stable ID tie-breaks. The aggregate network ranking is retained for compatibility, while line and transformer rankings are separate families.

Opt-in droop-response guard

droop_response_guard=true adds individual generator/controller Q headroom, bounded AC/droop-response prediction and controller-regime transition guards. It only changes screened branches to exact evaluation; it never changes exact or island-aware routes into screens. Unsupported or uncertain predictions fall back to exact AC. Pass the same participation weights used by subsequent exact assessment. The flag is supported by filtering, the integrated pipeline, qualification and resumable campaigns, and is included in campaign fingerprints. The default is false. See P2-02 qualification for the frozen protocol and current evidence; saved-case improvement is not held-out qualification or a security certificate.

Generic resumable campaigns and filtering qualification

run_contingency_campaign(directory, case, base_state) supports arbitrary networks and the integrated screened, exact, audited and island-aware routes. Set screening_enabled=false for the exhaustive AC reference. Its returned result is a ContingencyPipelineResult; resumed_count, evaluated_count and fingerprint describe reuse. Completion refers to the supplied catalog; a subset does not imply complete network N-1 coverage.

The atomic JSON checkpoints bind the complete case/catalog, saved base, participation, screening thresholds, audit IDs, numerical settings, code, Julia version and dependency files. A changed contract is rejected, not silently reused. Corrupt/incomplete checkpoints and evaluation errors are rerun. Saved states are revalidated and reranked; saved acceptance flags are not trusted. Invalid completed solves can be resumed as unresolved evidence. To retry with different settings, choose a new directory. The directory lock prevents concurrent writers; after a forcibly killed process, verify no writer is active before removing its stale .campaign-lock directory. Checkpoints provide process-interruption recovery, not a power-loss durability guarantee.

validate_contingency_filter(case, base_state) compares filter decisions with exhaustive AC routes on identical inputs, separately for lines, transformers and generators. It reports screened unresolved outcomes, screened physical failures, and counts found at each evaluation budget. Solver errors/rejections are unresolved, not proven infeasibility. Recall is undefined if there are no unresolved cases. Evaluation order is mandatory routes first, then descending predicted loading with stable ID ties; post-evaluation severity ranking remains a separate output. LODF factorization is reused across candidate transactions; nonfinite predictions and unsupported numerical conditions fall back to AC.

The default filter now additionally uses reactive_guard=0.1 and ac_risk_guard=true. The first compares aggregate upward/downward generator Q headroom with available Q range. The second escalates predicted apparent-flow loading and large impedance-based voltage-drop changes after redistribution. Neither is an AC solution or a mathematically certified bound. They only escalate: they cannot change an existing exact route into a screen. Generator outages remain exact. Both settings are included in campaign fingerprints; changed settings require a new campaign directory.

Response contract

All active/reactive powers and redispatch limits are per-unit on case.base_power; voltage magnitudes are per-unit and angles are radians. Positive P/Q means network injection. The reference bus fixes only its angle; it does not supply unbounded balancing power. All available generators retain their capability bounds.

Preventive mode uses a base schedule and limit-aware automatic active response:

\[P_{g,c}=\operatorname{clip}(P_{g,0}+\alpha_{g,c}\lambda_c,\ L_{g,c},\ U_{g,c}).\]

Effective bounds intersect generator and attached droop active capability with any declared base-to-outage redispatch_limits. A zero-weight unit holds its base output. Unavailable generators supply zero and are excluded. Zero-range units are excluded from normalized response weights. As the common signal grows, a participant at a bound stays there and unsaturated participants continue responding. If total reserve is inadequate, the model does not invent balancing power or relax operating bounds.

Study and assessment APIs default to default_participation(case): nonzero effective active-capability-range weights. Supply actual governor/AGC weights when known; the default is an explicit approximation. An explicit empty dictionary selects no participants and is rejected when an outage requires response. The surviving weights are normalized. Weights do not encode response speed.

The retained balancing_power result field contains the common request signal lambda, in pu. After saturation it is not the total delivered adjustment; calculate that from surviving generators' actual base-to-outage changes. The smooth reactive encoding uses an exact piecewise active projection (min/max) with kinks at saturation. The complementarity encoding uses projection KKT conditions with nonnegative bound slacks and multipliers. Both represent the same exact bounded active-response law. Coupled preventive CCOpt models default both the solver and proportional-update relaxation floors to 1e-14; supplied optimizer attributes can override these numerical defaults. This tightens the internal relaxation without changing physical acceptance tolerances. Projection slacks enforce equipment bounds without duplicate active variable-bound rows. A sole movable participant uses an equivalent canonical request-equals-delivery signal. It is not a smooth governor dynamic model; local convergence and saturation-boundary behavior require validation.

Current study/result JSON carries active_response="limit_aware_v1" (study v10, result v5). Historical coupled preventive files without this marker are rejected, rather than silently reinterpreted. Replay them with their original source. Campaign fingerprints include the response contract; use a fresh output directory for the new policy. Historical filtering thresholds and performance outcomes require requalification before use as evidence for this policy.

Corrective mode replaces this automatic-response equation with:

\[-r_g \le P_{g,c}-P_{g,0}\le r_g.\]

redispatch_limits[g] supplies the finite, nonnegative symmetric bound r_g. An omitted generator has zero permitted redispatch. This represents controlled post-contingency redispatch, without a time or ramp-rate model. Participation weights are rejected in this mode to avoid an ambiguous policy.

In both modes:

  • Unavailable generators inject zero P/Q and their droop equation is omitted.
  • Unavailable branches contribute neither admittance nor flow.
  • Available controlled generators obey their fixed Q(V) relation at the declared regulated bus in each scenario. No voltage setpoint is optimized.
  • Generators without a droop attachment retain M1's independently adjustable Q within capability limits. Attach controls to every unit when autonomous volt-var equilibrium is the intended experiment.
  • Loads, branch ratings, and voltage limits are unchanged across scenarios.
  • Disconnected base networks are rejected by the joint SCOPF formulation. Islanding outages use the separate retained-component assessment described above.
  • Reactive capability is M1's constant Q interval with a permitted P interval; a curved P-dependent capability boundary remains outside this implementation.

Equipment and reactive-control timing (M9.1)

Study may select continuous transformer ratios and simple-bank susceptances with the same TapControl and ShuntControl policies used by base-case design. Timing is explicit:

policy = SCOPFControlPolicy(
    taps = :corrective,       # default: scenario-specific within bounds
    shunts = :corrective,     # default: scenario-specific within bounds
    reactive = :automatic,    # the only supported reactive timing
    # Optional M9.2 maps: listed devices receive ± movement budgets;
    # selected but unlisted corrective devices are frozen.
    tap_movement_limits = nothing,
    shunt_movement_limits = nothing,
)

study = Study(case;
    contingencies,
    participation,
    reactive_assignments,
    tap_controls = [TapControl(11; lower=0.95, upper=1.05)],
    shunt_controls = [ShuntControl(201)],
    control_policy = policy,
)

Corrective equipment has an independent bounded setting in each scenario and is the default for selected tap and shunt controls. Preventive equipment has one setting shared by the base case and every scenario in which the device remains available; request it explicitly. These options may be selected separately for taps and shunts. A controlled transformer that is itself outaged has no contingency setting or coupling equation. This is availability, not corrective movement.

Reactive modes are automatic: the assignment, droop curve, AVR voltage target, FixedQ schedule, and regulated location are shared across scenarios, while Q, voltage, AVR limit regime, and the set of surviving common-location regulators respond to scenario physics. Scenario-specific voltage targets or droop parameters are not introduced. A branch-terminal regulator is disabled when its monitoring branch is outaged, as in the fixed-equipment SCOPF path.

Tap ratios and shunt susceptances remain continuous relaxations. Corrective timing asserts that movement is allowed in the modeled post-contingency stage; it does not supply a response time, switching count, discrete recovery, or dynamic feasibility claim. The caller is responsible for making that timing credible for the equipment represented.

M9.2 movement maps refine corrective timing. nothing retains M9.1 behavior: every selected corrective device may choose any setting inside its absolute control bounds. A supplied dictionary declares the allowed-action set. Listed devices satisfy abs(setting[c]-setting[base]) <= limit; selected devices omitted from the dictionary are frozen at their base setting. Limits are finite, nonnegative, and independently replayed by the validator.

Long assessments can solve the two M9.3 stages in separate processes and then call assemble_scopf_response_stages(immediate_study, settled_study, immediate, settled). This performs the same independent validation and metric assembly as assess_scopf_response_stages without rerunning either solve. The S2 public runner uses this path so an external wall timeout cannot erase a completed stage.

The process-isolated S2 example also supports a separate recovery lane that seeds a fixed-equipment solve from a direct SCOPF witness across every scenario. It is diagnostic evidence only: its outcome must not overwrite the declared FreeQ-base fixed-seed qualification lane. A physically replay-valid solution with a rejected solver status may be used as an initialization witness, but is still rejected for solver-acceptance reporting.

When the direct equipment-aware result is already independently valid, M9.3 may also be anchored directly to its saved base state and equipment settings. This is distinct from claiming success for a nominal-equipment staging lane. Reports must identify the anchor lineage and keep immediate, settled, physical-replay, and solver-acceptance outcomes separate.

The objective is the existing M1 base schedule-deviation objective:

\[\min \sum_g (P_{g,0}-P_g^{\rm initial})^2 + 10^{-3}(Q_{g,0}-Q_g^{\rm initial})^2.\]

Contingency states impose feasibility constraints without an additional cost. Consequently, corrective dispatch can be nonunique. This is not an economic SCOPF cost model. With no contingencies, the problem reproduces M1.

Solve and evaluate

study = Study(case;
    contingencies = [
        Contingency(:line_22; branch_ids = [22]),
        Contingency(:generator_9; generator_ids = [9]),
    ],
    participation = default_participation(case),
)
result = solve(study)
report = equilibrium_report(study, result)
println(markdown_report(report))

# Assess an existing base equilibrium without changing its dispatch or voltage.
evaluation = evaluate_contingencies(study, result.states[:base])

# Alternatively, allow bounded corrective redispatch.
corrective = Study(case; contingencies = study.contingencies,
    mode = :corrective, redispatch_limits = Dict(7 => 0.8, 9 => 0.8))
corrective_result = solve_scopf(corrective)

IDs refer to device IDs, not array positions. State vectors retain original case order, including zero entries for outaged generators. Results use :base and the contingency IDs as dictionary keys. No state is silently treated as feasible: a failed solve may return an infeasible iterate, or nothing if none is available. During fixed-base evaluation, the supplied base is independently validated but is not rebuilt as a redundant set of fixed equations in the NLP.

The default solver is Ipopt. optimizer_factory=MadNLP.Optimizer uses the same smooth formulation. encoding=:complementarity selects CCOpt and the exact PWL formulation; omit optimizer_factory for this encoding. Solver options are passed through optimizer_attributes.

solve_scopf_continuation(study; smooth_epsilons=[1e-2,1e-3,1e-4]) returns the sequence of results, warm-starting all scenario states. It stops after solver failure or a missing state. Independently validate the final result. For other initial points, pass a dictionary through initial_states to solve_scopf.

Equipment variables use each control's initial value. For difficult joint models, first solve the fixed-equipment SCOPF and pass its scenario states as a staged start; then seed a corrective run's control initials from the validated preventive settings. A solver's infeasible termination is retained and is not treated as a physical infeasibility certificate.

result.tap_settings and result.shunt_settings are scenario-indexed maps of the selected controls only. Fixed-base evaluation accepts an ACState; studies with selected equipment must also pass the exact saved base maps through fixed_base_tap_settings and fixed_base_shunt_settings. Missing or extra settings are rejected rather than guessed.

M9.3 pairs two assessments around that same saved base:

assessment = assess_scopf_response_stages(
    immediate_preventive_study,
    settled_corrective_study,
    validated_base_result,
)
write_scopf_stage_assessment("stages.json", assessment)
println(markdown_report(assessment))

The immediate study must freeze taps and shunts. The settled study may apply M9.2 budgets. The report compares voltage, thermal and generator-Q margins plus equipment movement. It represents two steady-state equilibria, not elapsed time, dynamics, switching sequences, or transient stability.

Independent acceptance checks

equilibrium_report(study, result) rebuilds the outage cases and checks AC balance, both ends of branch flows, generator and voltage limits, exact droop replay, disabled generators, reference angles, active-response coupling, and equipment timing. For every scenario it reconstructs a physical network from the reported tap and shunt settings before calculating residuals. Missing, out-of-bounds, nonfinite, or unexpectedly present settings are rejected; for preventive controls, deviation from the base setting is reported separately as equipment_coupling_violation. The report records tolerances and scenario-specific failures.

  • physical_valid requires exact-curve equilibrium and all physical/coupling checks.
  • encoded_physical_valid checks the numerical droop encoding in place of exact replay.
  • valid additionally requires a successful solver termination. For a fixed-base evaluation with no contingencies there is no optimization; status is :NOT_RUN and independent feasibility alone determines validity.

The report lists exact and encoded droop residuals separately, along with their smoothing gap. Default power/limit/coupling tolerances are 1e-6, exact and encoded droop tolerance is 1e-5, and unavailable-generator tolerance is 1e-8. Tolerances are explicit keyword arguments. These checks certify only the reported equilibrium to those tolerances, not global optimality, uniqueness, transient stability, or frequency response.

Reproducibility

Run from the repository root:

julia --project=. examples/m2_workflow.jl /tmp/droopopf-m2

The example writes a study, result, and validation report as JSON, plus a Markdown report. It reloads the JSON files, independently validates the restored result, and deliberately corrupts an outage result to demonstrate rejection.

The M9.1 workflow stages a preventive continuous tap/shunt SCOPF from a fixed-equipment witness, then solves a separately declared corrective-timing study. Both are independently validated and persisted:

julia --project=. examples/m9_1_equipment_scopf.jl /tmp/droopopf-m9-1
write_study("study.json", study)

Visual validation

The end-to-end workflow writes nine self-contained SVG figures. Five detailed operating plots are retained:

  • m2_droop_operating_points.svg overlays base and contingency operating points on the exact volt-var curves. Marker shape identifies the scenario; curve colour identifies the control.
  • m2_bus_voltages.svg compares each bus across scenarios and shows its allowable voltage interval behind every operating point.
  • m2_branch_loading.svg reports apparent-power loading as a percentage of rating, draws the 100% threshold, and marks outaged branches with a cross.
  • m2_generator_dispatch.svg compares active and reactive generation and marks outaged generators.
  • m2_validation_residuals.svg plots AC-balance, exact-droop, and response residuals divided by their acceptance tolerances. The horizontal threshold is one; bars below it pass.

Four cross-scenario evaluation plots connect declared inputs to independently checked outputs:

  • scopf_declared_inputs.svg lists each outage, active-power response policy, and preventive/corrective tap and shunt timing;
  • scopf_operating_margins.svg shows voltage, thermal, generator-P, and generator-Q margins, with near-limit and violated cells highlighted;
  • scopf_response_deltas.svg compares maximum voltage, angle, active-power, and reactive-power changes from the saved base state on a logarithmic scale;
  • scopf_validation_matrix.svg maps every scenario to independent state, balance, droop/AVR, voltage, thermal, capability, availability, response, and equipment checks. It is intentionally writable for invalid results so negative controls and failed solves can be investigated visually.

Generate the complete bundle with:

paths = write_scopf_validation_plots("m2-validation", study, result)

Individual writers are available when only one view is needed: write_scopf_droop_plot, write_scopf_voltage_plot, write_scopf_branch_loading_plot, write_scopf_dispatch_plot, and write_scopf_residual_plot. A missing scenario state or a result whose scenario set differs from the study is rejected instead of producing a partial figure. The graphics explain a validated result; the independent numerical report remains the acceptance authority.

JSON documents use a document-kind tag. Study schema v10 and result schema v5 persist optional reactive-control assignments, selected tap/shunt policies, the timing/movement policy, and scenario equipment settings, with an explicit limit-aware active-response marker. Historical coupled preventive documents without the marker require their original source for replay. Supported uncoupled and corrective documents retain the existing equipment/attachment migrations. Selected equipment policies default to corrective timing; unselected taps and shunts remain supplied fixed data. Study files contain all case data, contingencies, and response policy. Result files contain scenario states, active-response request signals, equipment settings, solver/status, encoding, and smoothing widths. Nonfinite diagnostics are written as JSON null; missing states remain null. Report files are diagnostic exports; reports are regenerated from study/results, not trusted as proof of validity.
