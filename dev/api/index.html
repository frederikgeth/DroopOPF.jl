DroopOPF.Study — Type
Study(case; contingencies=[], mode=:preventive, participation=nothing, redispatch_limits=Dict(),
      tap_controls=[], shunt_controls=[], control_policy=SCOPFControlPolicy())

Fixed-curve SCOPF study. Preventive automatic response follows weighted requests clipped to each participant's effective active bounds and optional movement limits. A common response signal lets unsaturated generators take over unmet response. Default weights use nonzero effective active capability ranges; explicit weights override them. Zero-weight generators hold their base output. The signal is power in p.u., not frequency, and differs from total delivered response after saturation. Corrective response permits abs(P[c,g] - P[base,g]) <= redispatch_limits[g]. Missing limits mean zero redispatch. Limits also optionally cap preventive response. All powers use the case per-unit base. Generator capability limits apply in every scenario. Outaged generators have zero P/Q and no active droop equation.

DroopOPF._build_complementarity_opf_model — Method

Build an exact PWL-droop AC OPF model for CCOpt.

Each voltage hinge is represented as $z >= 0 ⟂ z - a >= 0$. Reactive clipping is the KKT system of projection of the raw droop value onto the reactive capability interval. Positive-width deadbands use four pairs per attachment. Constant zero-width deadbands use the affine raw response directly and only the two reactive projection pairs, avoiding redundant voltage hinges.

DroopOPF.assess_contingency_pipeline — Method
assess_contingency_pipeline(case, base_state; ...)

Run a coverage-checked M10 assessment pipeline. Every catalog entry receives exactly one route. audit_screened_ids names screened entries that must also receive exact evaluation. Set screening_enabled=false for an exact connected- outage baseline. Evaluation errors are retained unless continue_on_error=false. workers=1 preserves serial execution. Larger values use bounded threaded batches with independent models, serial native solves, and deterministic coordinator callbacks/checkpoints. Start Julia with enough threads. Phase timings sum worker durations and are not parallel wall time. User model hooks, if supplied, must be thread-safe.

DroopOPF.build_global_feasibility_model — Method

Build a bounded voltage-restoration model for a frozen fixed-equipment problem.

mode=:global uses rectangular AC voltages and exact SOS2 droop regions. mode=:soc uses sparse edge-product SOC envelopes and droop graph convex hulls. Only target_bus may exceed its original upper voltage bound, by delta in [0,max_relaxation]. Frozen feasibility tolerances are included in both models. The SOC model is an outer relaxation, never a feasible-point certificate. Angle windows outside (-pi/2,pi/2) are explicitly omitted (an outer relaxation). Pass an optional global/conic solver factory; no optimization occurs here.

These are final relaxed-NLP metrics, not an original-MPCC stationarity proof. source
DroopOPF.certify_feasibility_lp — Method

Try a sparse outer LP and return only independently verified infeasibility.

The optional LP solver supplies candidate Farkas multipliers. The checker uses exact rational arithmetic, including residual stationarity errors over finite variable bounds. SOC/thermal tangent cuts are independently validated. Optional psd_clique_limit (0 disables; 3–32 enables) adds bounded-size cycle PSD support cuts, whose rational coefficients are reconstructed independently. Feasible LP points never qualify the original nonconvex problem. The work is bounded by time_limit and max_rounds; no global solver is required by the main package.

source
DroopOPF.check_feasibility — Method

Replay seeds, check global necessary conditions, then optionally search locally.

A local failure, positive local restoration objective, or absence of a witness returns :unresolved. :certified_infeasible requires an independently replayed certificate. Optional lp_options and global_options select bounded escalation backends; neither runs by default. Solver-reported global bounds alone do not upgrade the gate. Inconclusive certificates or unsupported backends are unresolved.

source
DroopOPF.check_psse_file — Method

Check a RAW saved power-flow solution and optionally save a JSON report.

This check-only path never exposes a case with invented thermal ratings. It uses an internal finite adapter placeholder for zero/omitted ratings solely to replay AC physics, excludes those placeholders from every thermal check, and reports incomplete thermal coverage. Ordinary load_psse_case still requires an explicit unrated_limit before it can return such a case. Unsupported data return status="unsupported"; malformed input returns status="invalid_file".

DroopOPF.filter_contingencies — Method
filter_contingencies(case, base_state; loading_threshold=0.8, voltage_guard=0.02)

Route N-1 candidates before exact AC evaluation. Generator outages always go to exact evaluation. Islanding branches go to the island-aware path. Connected line and transformer outages use a lossless DC LODF prediction; numerical uncertainty and a tight base-voltage margin fall back to exact evaluation. reactive_guard=0.1 escalates when aggregate bidirectional Q headroom is at most 10% of available Q range. ac_risk_guard=true also checks apparent-flow redistribution and an impedance-based incremental voltage-drop indicator. These are escalation heuristics, not AC power-flow solutions or bounds. Set reactive_guard=0, ac_risk_guard=false to replay the legacy policy. Opt-in droop_response_guard=true adds individual Q-reserve and bounded AC/droop-response risk checks for fixed-equipment legacy droops. Unsupported or uncertain predictions escalate to exact AC; the default remains unchanged. participation must match the subsequent fixed-base exact evaluation.

DroopOPF.load_matpower_case — Method
load_matpower_case(path; base_frequency = 50.0, id = nothing)

Load the core bus, generator, load, and branch tables from a MATPOWER v2 case file. Values are normalized to the case base power. TAP=0 maps to unity; SHIFT is converted from degrees to radians. DroopOPF.optimize_multi_period_security — Method

Optimize shared droop across ordered periods and listed contingencies.

response=:s2_proportional preserves supplied weights without saturation; :limit_aware uses the production response model. s2_emergency=true explicitly selects S2's ±0.05 pu voltage extension, 1.1 thermal ratings, 1% per-load DR, 10 MW shedding per outage, 10% combined relief, proportional reactive relief. Base cases always use original bounds/full load. Objectives are sequential: minimum total shedding, minimum total DR, then duration-weighted base loss. objective_policy=:reserve_loss inserts maximization of the minimum participating-generator upward-headroom fraction before loss; :reserve stops after the reserve stage. This is a dispatch preference, not an outage-security certificate. Equipment follows each Study policy; ramps link preventive dispatch only. Optional avr_bounds schedules preventive targets with movement in pu/hour; otherwise all supplied targets remain fixed. Optional reserve_generator_outages requires surviving participation to have upward room for each named generator's entire base output plus reserve_margin_pu, before any load relief. This explicit reserve target does not account for changed losses or replace exact outage AC. Retain this extra policy externally with the input studies for independent audit. objective_policy=:feasibility seeks a constrained witness without resource or loss optimization. Each initial-equipment entry may carry a scenarios dictionary of per-scenario taps/shunts starting values, falling back to its period entry. These starts do not change equipment bounds, timing, movement budgets or shared constraints. initial_avr_targets, initial_relief and initial_balancing_power retain the remaining primal variables across retries; each supplies one dictionary per period. Unknown scenario/target IDs, nonfinite values and inconsistent shared targets are rejected. AVR and individual relief starts are clipped to variable bounds. No manufacturer timing is inferred.

DroopOPF.run_contingency_campaign — Method
run_contingency_campaign(directory, case, base_state; ...)

Run the integrated pipeline with atomic per-outage JSON checkpoints. Resume requires identical case, catalog, base state, participation, screening/audit policy, solver settings, Julia version, source and dependency environment. Mismatched contracts are rejected without overwriting prior evidence. Corrupt checkpoints and evaluation errors are rerun; saved states are independently revalidated. A directory lock prevents concurrent writers. on_checkpoint is a progress callback after durable writes (and can interrupt the campaign). Returns (result, resumed_count, evaluated_count, fingerprint).
