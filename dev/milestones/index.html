Milestone and evidence index

Implementation, numerical qualification and research closure are separate statuses. The release scope records the current supported boundaries. Original campaign policies remain attached to their results; later success does not rewrite an earlier failure or migrate historical S2 results to P2 semantics.

Evidence structure

Each submilestone should identify its scope and assumptions, model equations, runnable example, machine-readable results, readable report and specified figures/tables. Acceptance separates native solver termination, physical replay, operating limits and control-policy compliance. A numerical failure is unresolved unless separate evidence establishes infeasibility under the stated contract.

Sealed campaigns additionally record input/source hashes and output manifests. Historical layouts vary; not every early milestone has the same folder template. The research archive guide explains how to recover full records.

For future reports, record the date, source revision, input identity, network and contingency coverage, objective, control sharing, movement/timing assumptions, acceptance tolerances, rejected attempts, independent replay and remaining gates. Keep new campaigns separate when any physical or information policy changes.

Documentation maintenance

Update this index and the release scope when qualification changes. Keep historical outcomes labelled by campaign; link current summaries to compact evidence with provenance. Package CI and documentation builds establish software integrity, not renewed acceptance of every archived large-network experiment.
